# Проект bmw-names — контекст для Claude

Этот файл — живая память проекта. **Прочитай его целиком, прежде чем вносить
изменения.** Он всегда лежит в репозитории рядом с кодом; новый чат начинается
с «подключи `mersamatruh/bmw-names`, прочитай `CONTEXT.md`». Вырезки из чатов
делать не нужно — держим актуальным этот файл.

## Что это

Веб-хаб из нескольких подпроектов под общим меню слева. Первый и основной —
**«Названия»**: генерация наименований запчастей BMW по методике владельца
(онлайн-таблица → сервер через Claude API даёт наименование + SEO,
самообучение на правках). Второй — **«Бот напоминатель»**: регулярные платежи,
напоминания в Telegram. Дальше будут ещё подпроекты, каждый — отдельным модулем.

Пользователь — не программист. Объяснять просто, пошагово, команды давать по
одной (его терминал теряет спецсимволы `|`, `$()`, `<` при ручном НАБОРЕ; при
вставке — ок). Файлы службы/настроек лучше давать готовыми (scp), а не heredoc.
Общение на русском.

## Модульная архитектура (с версии 3.0)

Код разбит на ядро + подпроекты-модули, чтобы разные проекты можно было вести в
разных чатах/ветках без конфликтов по одному файлу.

- **server.py — ядро.** Flask-приложение, вход по паролю (`check_auth`,
  заголовок `X-Auth`), оболочка страницы (шапка, боковое меню, область разделов,
  логин), механизм обновления, и сам раздел **«Названия»** (он остаётся в ядре —
  сложный и завязан на generate_names.py). При старте ядро **само находит все
  `mod_*.py`** рядом (`_load_modules`) и собирает из них меню, разделы, CSS и JS.
- **Контракт модуля.** Файл `mod_<имя>.py` определяет функцию
  `register(ctx)` и возвращает словарь
  `{id, title, section_html, css, js}`. Через `ctx` модуль получает
  `app, check_auth, lock, jsonify, request, data_dir` и сам регистрирует свои
  `/api`-маршруты. JS модуля кладётся отдельным `<script>` (поломка модуля не
  роняет ядро). Ядро вызывает `window['onShow_<id>']()` при открытии раздела
  (модуль так подгружает данные). Модулям доступны глобально `api`, `apiGet`, `$`.
- **Текущие модули:** `mod_reminders.py` — раздел «Бот напоминатель»;
  `mod_sales.py` — раздел «Анализ продаж» (анализатор продаж Porsche).
- **Новый подпроект = новый файл** `mod_<имя>.py` + его имя в `files.json`.
  Чужие файлы не трогаются. Так два подпроекта никогда не конфликтуют.

## Код и обновления

- **GitHub: mersamatruh/bmw-names (public), ветка main.** Claude подключает
  репозиторий (add_repo) с push-доступом; пользователь подтверждает подключение.
- **Файлы проекта в репозитории:** server.py, mod_*.py, files.json, CONTEXT.md.
  `generate_names.py` и данные — НЕ в репозитории (только на сервере).
- **files.json** — манифест: список файлов, которые тянет обновление. Добавил
  модуль → допиши его имя сюда.
- **Цикл обновления:** Claude правит → тестирует локально (стабы anthropic и
  generate_names, Flask test_client, при желании скриншот через playwright) →
  commit+push → пользователь жмёт **«Обновить с GitHub»** (кнопка в шапке,
  справа от версии). Сервер читает
  files.json с raw.githubusercontent, скачивает все файлы, проверяет их
  (compile + маркеры в server.py), бэкапит, пишет и перезапускается (os.execv).
  Если манифест недоступен — страховка: обновляет только server.py.
- **Вливать в main сам, без «влей»** (решение владельца 15.10.2026): после
  проверки Claude открывает PR и сразу его вливает, затем говорит нажать
  «Обновить с GitHub».
- **Кеш GitHub raw ~5 минут** после пуша — предупреждать «подождите 5 минут».
- **Версия:** константа VERSION в server.py, показывается в шапке + авто-время
  публикации (момент записи server.py, МСК). Схема (с 3.0):
  **X.0** — новый раздел/подпроект/крупное; **X.Y** — правки без структурных
  изменений; мелкие правки — сотые:
  4.61, 4.62, … (просьба владельца — версии менять реже). Текущая: 4.64. Поднимать при каждом изменении (это и индикатор, что
  обновление встало).
- **Аварийный путь:** scp файлов в /root/bmw_names + `systemctl restart bmw-names`,
  либо скрытый endpoint /api/update_code (принимает .py/.zip).

## Раздел «Названия» (в ядре server.py)

- Генерация: RAG-lite — find_similar (похожие эталоны по словам базового названия
  + пересечению кузовов) + методичка → Claude с web_search. Логика промпта в
  **generate_names.py** (рядом на сервере, в репозитории его НЕТ — менять промпты
  там, возить вручную через scp).
- Партии = «слепки» (snapshots): фоновые воркеры (threading), браузер опрашивает
  /api/job. Результат пишется в слепок сразу, можно закрывать браузер.
- SEO: отдельный воркер. Формат утверждён: предметный заголовок без «купить»,
  «новая оригинальная BMW», симптомы живым языком, применимость с расшифровкой
  кузовов, финал строго «Проверим применимость по VIN… Оригинальный артикул: X.»
- CATALOG: нормализация norm_art_key (верхний регистр, без пробелов/дефисов,
  без ведущих нулей). Автопополнение из ручных правок и /api/feedback.
- Обучение: ✓ и правка → dataset.jsonl + слепок; ✎ — причина → методичка.
- Таблица (vanilla JS в PAGE): Excel-подобное выделение/копирование/вставка,
  фильтры, точечная перерисовка, защита правленных строк (_dirty, _pin).
- Расходы: add_cost по usage (PRICES), шапка «$X сегодня / $Y всего», costs.json.

## Раздел «Бот напоминатель» (mod_reminders.py + отдельный Telegram-бот)

- **Данные на сервере — источник правды:** reminders.json ({seq, items, marks}).
  items = {id, name, start_day, end_day, active}; marks = {rid, period "YYYY-MM",
  at, by}. API (в модуле): GET /api/reminders, POST /api/reminder_add,
  /api/reminder_archive, /api/reminder_period; GET /api/marks?period,
  POST /api/mark, /api/unmark. Всё под X-Auth.
- **Веб-панель** (раздел): создать напоминание (название + окно дней «1-14»),
  список, архив (удаления нет — только архив, история сохраняется).
- **Telegram-бот paybot** — ОТДЕЛЬНЫЙ процесс, НЕ в этом репозитории.
  Живёт в /opt/paybot (венв, paybot.py, bot.env), systemd-служба **paybot**.
  Читает напоминания и пишет отметки через API ядра по localhost
  (API_BASE=http://127.0.0.1:8090, API_PASSWORD = тот же APP_PASSWORD).
  Каждое утро (по умолч. 9:00 МСК) пишет в привязанный чат про открытые
  неоплаченные, кнопка «Оплачено» ставит отметку на месяц. Доступ по чату:
  OWNER_IDS (владелец, настройка) + любой участник привязанного чата (/here).
  Состояние бота (chat_id, remind_hour, last_sent) — локальный paybot_state.json.
- Есть ещё первый бот учёта расходов по машинам (/opt/bot, служба bot) —
  к этому проекту прямого отношения не имеет.

## Раздел «Анализ продаж» (mod_sales.py) — анализатор продаж Porsche

- Пробная версия (4.1): онлайн-таблица, колонки: артикул, артикул замены
  (маска A-Z0-9, кириллица-двойники → латиница), наименование (из своего
  справочника sales_catalog.json по артикулу, иначе по замене), прибыль склад
  за период, оборот Герм., продано за период Герм./поставщики/склад, общие
  продажи (сумма трёх, авто), в заказ (расчёт), комментарий, наличие,
  кол-во заказано, в пути (часть заказанного, уже выехало), продажи за год.
- «В заказ» пока формулой: спрос/день = 0.6·(общие/период) + 0.4·(год/365)
  (если одного нет — берётся другой); нужно = спрос × дней запаса;
  в заказ = ceil(нужно − наличие − заказано), не меньше 0. «В пути» уже
  входит в «заказано». Период и запас (дни) — настройки над таблицей.
  Дальше: правила владельца + ИИ.
- Слепки как в «Названиях»: открытый слепок автосохраняется; «Новая партия»
  очищает таблицу, новый слепок (ГГГГ-ММ-ДД_чч-мм-сс) создаётся при первой
  записи; список/Открыть/Удалить. «В заказ» — рыжая колонка, редактируемая:
  ручное число хранится в order_manual (пусто → снова расчёт); при вставке
  блока из нескольких колонок «в заказ» не перезаписывается.
- Период продаж — даты «с/по» (хранятся в слепке, дни считаются сами).
  Запас по умолчанию 60 дн. (2 месяца). Правка «В заказ» → окно «Объясни
  почему?» (причина обязательна, Enter — сохранить); колонка ✓/✎ справа от
  «В заказ»: ✓ расчёт принят, ✎ правка (клик — изменить причину/вернуть
  расчёт). Правки пишутся в sales_lessons.json (ключ слепок+артикул, история
  причин сохраняется). Массово в «В заказ» можно только очистить.
- Колонка № (поле n): постоянный номер строки по порядку вставки, при
  сортировке/фильтрах не пересчитывается. Под заголовками — фильтры по
  колонкам (текст содержит; для чисел >5, <=3, =0; «пусто»/«не пусто»; ✓/✎),
  клик по заголовку — выделение всего столбца (Shift — несколько), значок ⇅ — сортировка ▲▼ (физически меняет порядок строк). Шапка с фильтрами закреплена: у #slTable overflow:visible, иначе общий overflow:hidden у table ломает sticky.
  «↺ Вернуть исходный порядок» снимает фильтры/сортировку и выстраивает по №
  с перенумерацией 1..N.
- Выделение блока ячеек (мышью/Shift+клик): Ctrl+C копирует TSV (ловится keydown по e.code — работает и в русской раскладке и без фокуса; одна ячейка копируется целиком), Delete
  очищает, Ctrl+V вставляет с левого верхнего угла, Esc снимает.
- Ввод: Ctrl+V блока из Excel в любую ячейку (столбцы по порядку колонок
  таблицы, вычисляемые пропускаются; галочка «Убирать заголовок при вставке»,
  по умолч. вкл., отбрасывает первую строку вставки — владелец вставляет
  столбцы с названием в первой ячейке), автосохранение, экспорт CSV.
- API: GET /api/sales, POST /api/sales_save, /api/sales_names,
  /api/sales_catalog_add (текст «артикул<TAB или ;>наименование»),
  /api/sales_catalog_upload (файл xlsx/xls/csv: A — артикул, B — наименование,
  строка заголовка распознаётся и пропускается; pandas+openpyxl как в ядре).

## Правила методики наименований (кратко)

1. Кузовная деталь: префикс 1–4 популярных кузова через «/» (F30/F31), не все.
2. Моторная: префикс индексов двигателя (B37, N57/M57) — определять web-поиском;
   трансмиссия — индекс агрегата (8HP80, 7DCT300).
3. Двери/фары/фонари — строгие паттерны. Крепёж без префикса. Диски — стиль (556M).
   Полные правила — в metodika_naimenovanij.md на сервере.

## Как начать новый подпроект (чек-лист)

1. Новый чат: «подключи mersamatruh/bmw-names, прочитай CONTEXT.md». Подтвердить
   подключение GitHub. Склонировать, сверить свежий main.
2. Создать `mod_<имя>.py` по контракту (register(ctx) → {id,title,section_html,
   css,js}, свои /api). За образец — mod_reminders.py.
3. Добавить имя файла в `files.json`.
4. Протестировать локально (стабы anthropic + generate_names, test_client,
   скриншот). Поднять VERSION (новый раздел → X.0).
5. commit+push. Пользователь жмёт «Обновить с GitHub» (ждёт ~5 мин кеша).
6. Данные подпроекта — свой файл в /root/bmw_names (как reminders.json),
   адресовать через ctx["data_dir"].

## Дисциплина параллельной работы

- В один момент конкретный файл правит один чат. Разные модули = разные файлы →
  не конфликтуют. Общий `server.py` правит тот, кто занят ядром/«Названиями».
- **Перед правкой всегда подтянуть свежий main** (git fetch + reset --hard
  origin/main в чистой копии) — иначе можно затереть чужое.

## Известные грабли

- Облачная среда Claude НЕ достаёт до names.elalameyn.ru по curl (egress только
  реестры пакетов и GitHub). Страницу можно читать через WebFetch. Прямого push
  на сервер нет — поэтому путь через GitHub.
- У пользователя бывает корпоративная сеть (Squid), которая **режет SSH порт 22**
  (таймаут), хотя сайт по 443 работает. Обход: раздать интернет с телефона
  (мобильная сеть) и зайти по SSH оттуда; запасной путь — веб-консоль Hetzner
  (панель → сервер → Console, работает по 443).
- API-ключ Anthropic работает с сервера (Германия); с ПК пользователя (Россия)
  API недоступен (403 region). Ключи/пароли в чат не писать; при утечке —
  ротация.
- Telegram API с ПК пользователя тоже может блокироваться провайдером —
  боты поэтому живут на сервере.
- Локальный тест server.py: anthropic и generate_names подменяются стабами,
  Timer/execv можно замокать, APP_PASSWORD через env; generate_names.py и
  dataset.jsonl нужны рядом (импортируется как gn).

## Невыполненное / идеи

- Статус «оплачено» показывать в самой веб-панели напоминаний (данные в
  /api/marks уже есть).
- Автобэкап dataset.jsonl + metodika + catalog.json (напр., в GitHub по
  расписанию). Пока — вручную через scp.
- Порог дневного расхода с предупреждением в шапке.
- Чистка раздела «Работа над ошибками» методички по мере роста.
- На сервере висит `System restart required` — перезагрузить на днях (службы на
