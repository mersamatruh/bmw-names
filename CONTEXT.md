# Проект bmw-names — контекст для Claude

Этот файл — сжатая память предыдущего чата. Прочитай его целиком, прежде чем вносить изменения.

## Что это

Веб-система генерации наименований запчастей BMW по методике владельца:
онлайн-таблица, куда вставляются артикулы; сервер через Claude API генерирует
наименования по паттерну (кузовной/моторный префикс + описание) и SEO-описания
карточек товара. Система самообучается на правках пользователя.

Пользователь — не программист. Объяснять шаги просто, пошагово, команды давать
по одной (его терминал теряет спецсимволы `|`, `$()`, `<` при ручном наборе).
Общение на русском.

## Файлы данных на сервере (/root/bmw_names) — ЦЕННОЕ, бэкапить

- `dataset.jsonl` — ~7300+ эталонов «вход → наименование», растёт от правок.
- `metodika_naimenovanij.md` — правила методики + раздел «Работа над ошибками».
- `catalog.json` — справочник артикул → базовое название (~312 тыс. позиций).

## Код и обновления

- **GitHub: mersamatruh/bmw-names (public), ветка main, файл server.py.**
  Claude имеет push-доступ через привязанный GitHub пользователя.
- Цикл обновления: Claude правит код → тестирует локально (stub anthropic,
  запуск Flask на локальном порту, проверка токенов в HTML) → commit+push →
  пользователь жмёт кнопку **«Обновить с GitHub»** на странице. Сервер скачивает
  raw.githubusercontent.com/mersamatruh/bmw-names/main/server.py, валидирует
  (compile + маркеры), бэкапит, пишет и перезапускается через os.execv.
- **Кеш GitHub raw ~5 минут** после пуша — предупреждать пользователя «подождите
  5 минут» или писать «можно жать».
- **Версионирование обязательно:** константа VERSION ("X.Y от DD.MM.YYYY") в
  server.py, показывается в шапке страницы — по ней пользователь проверяет,
  встало ли обновление. Поднимать при каждом изменении. Текущая: 3.8 от 12.10.2026.
- Аварийный путь обновления: endpoint /api/update_code (принимает .py/.zip
  multipart, кнопка скрыта) или scp + systemctl restart bmw-names.

## Архитектура server.py (Flask, всё в одном файле)

- Генерация имён: RAG-lite — find_similar (15 похожих эталонов по словам
  базового названия + пересечению кузовов) + методичка → claude-sonnet-4-6
  с web_search (до 3 поисков; для моторных деталей ищет мотор по артикулу).
  Логика промпта импортируется из generate_names.py (лежит рядом на сервере!
  менять промпты — там). Ответ JSON {наименование, обоснование}.
- Партии = «слепки» (snapshots): фоновые воркеры на сервере (threading),
  браузер только опрашивает /api/job раз в 2 c. Результат каждой строки пишется
  в слепок сразу. Можно закрывать браузер.
- SEO-описания: отдельный воркер (кнопка «Сгенерировать SEO»), формат утверждён:
  предметный заголовок без «купить», «новая оригинальная BMW», симптомы живым
  языком, применимость с расшифровкой кузовов, финал строго «Проверим применимость
  по VIN по вашему запросу. Оригинальный артикул: X.» Без аналогов/цен/доставки.
- Справочник CATALOG: нормализация артикула norm_art_key — верхний регистр,
  без пробелов/дефисов, ведущие нули отбрасываются (07149... == 7149...).
  Автопополнение: вручную вписанное базовое название незнакомого артикула
  уходит в справочник; /api/feedback тоже пополняет.
- Обучение: ✓ (принято) и правка названия → dataset.jsonl + слепок; кнопка ✎ —
  комментарий-причина → в методичку. Правка названия сохраняется автоматически
  по клику вне поля (без диалогов).
- Таблица (фронт, vanilla JS в PAGE): колонки № / Артикул / Кратк. (посл. 7
  символов, вычисляемая) / Базовое / Применимость / Наименование / SEO
  (свёрнуто, клик разворачивает) / Статус / Действия (✓ ✎ ↻).
  Выделение ячеек как в Excel (клик, drag, Shift+клик, Shift+стрелки),
  копирование через событие copy (работает на любой раскладке), вставка
  Ctrl+V в выделенную ячейку/диапазон без входа в редактор; чистка вставки:
  артикул — маска A-Z0-9 + uppercase, остальное — убрать управляющие/невидимые
  символы и лишние пробелы. Редактор наименования — авторастущая textarea
  (dblclick/Enter), сохранение по blur, Escape — отмена. Точечная перерисовка
  строк (updateRow), строка под редактором не трогается (pendingSrv),
  правленные строки защищены _dirty (от опроса) и _pin (от скрытия фильтрами).
  Фильтры по колонкам + селект статуса. Кнопки btnAdd и btnCsv скрыты
  display:none (логика жива).
- Расходы: add_cost считает $ по usage каждого ответа (цены в PRICES — вход $3,
  выход $15 за MTok, web-поиск $10/1000), показывается в шапке
  «$X сегодня / $Y всего», хранится в costs.json. Остаток баланса через API
  недоступен — только console.anthropic.com.
- Статусы строк: wait/run/done(Проверить)/ok(Принято)/fixed(Исправлено)/err.
  err при пустом базовом: «Артикула нет в справочнике — впишите базовое название»;
  текст ошибки показывается под статусом. Ввод названия в такую строку пишет
  его в ОБА поля (base и name), статус fixed, строка блокируется от генерации.

## Правила методики наименований (кратко)

1. Кузовная деталь: префикс 1–4 популярных кузова через «/» (F30/F31), не все 30.
2. Моторная: префикс индексов двигателя (B37, N57/M57) — определять web-поиском
   по артикулу, если неизвестен; трансмиссия — индекс агрегата (8HP80, 7DCT300).
3. Двери/фары/фонари — строгие паттерны (дверь передняя левая и т.п.).
4. Крепёж без префикса. Диски — номер стиля (556M). Полные правила — в
   metodika_naimenovanij.md на сервере.

## Известные грабли

- Claude's облачная среда НЕ достаёт до names.elalameyn.ru по curl (egress
  только реестры пакетов и GitHub). Страницу можно читать через WebFetch.
  Прямой push файлов на сервер невозможен — поэтому и сделан путь через GitHub.
- У пользователя корпоративный прокси (Squid): порт 8080 для него был закрыт,
  браузер блокирует скачивание .py («Unverified download blocked») — поэтому
  исторически возили zip; теперь неактуально (GitHub-кнопка).
- API-ключ Anthropic работает с сервера (Германия); с компьютера пользователя
  (Россия) API недоступен (403 region). Ключ и пароль в чат не писать; один
  ключ уже засвечивался — рекомендована ротация.
- При тестах server.py локально: модуль anthropic подменяется стабом,
  os.execv монкипатчится, ANTHROPIC_API_KEY/APP_PASSWORD через env.
  generate_names.py и dataset.jsonl нужны рядом (импортируется как gn).
